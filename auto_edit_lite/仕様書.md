# TikTok Shop 自動編集ツール 仕様書

## 1. 目的・背景

AnyMindのTikTok Shop事業で大量の動画投稿を行うにあたり、編集未経験のスタッフでも
素材を出すだけで一定品質の編集済み動画が自動生成される仕組みを構築する。

最終形は、素材をGoogle Driveの指定フォルダに置くだけで裏側のクラウド処理が自動的に
編集・書き出しを行う完全自動化（Phase3）。素人ユーザーは一切プロンプトやコードを
見ない運用とする。

開発自体はClaude Codeで行うが、本番稼働はClaude Code無しで動作するクラウド基盤
（GCP Cloud Run想定）に乗せる。開発・保守は現状ユーザー1人。

## 2. IP非公開方針

| 項目 | 扱い |
|---|---|
| 非公開スキル `tiktok-short-edit`（字幕ピクセル配置計算式・配色コード・タイミング計算式・VOICEVOX設定・SFX/ズームバンプ演出・話者ピッチ判定） | 簡易版には**絶対にコピーしない** |
| 「なぜ伸びるか」の判断ロジック（フック文言の作り方・PAS構成・CTAの打ち方） | Phase2のAI判断層(`edit_brain.py`)には反映してよい |
| Phase2のプロンプト・ロジック自体 | 素人ユーザーには**絶対に見せない・配布しない**（構造的にDriveフォルダ操作のみで済む設計で担保） |

## 3. 全体アーキテクチャ（3フェーズ）

| フェーズ | 内容 | 状態 |
|---|---|---|
| Phase1 | ローカル試作: ffmpeg無音カット + faster-whisper文字起こし + 単一スタイル字幕焼き込み（縦型1080x1920） | 実装済み（本リポジトリ `auto_edit_lite/lite_edit.py`）。クラウド開発環境でffmpeg・faster-whisperを実際に動かし一連の動作を再確認済み（合成テスト素材）。素材が無音で始まる/終わるケースで無音を発話と誤検出するバグを発見・修正済み（詳細は本ファイル末尾の注記）。実機（自宅Mac・本物の素材）では未検証 |
| Phase2 | AI判断層: 長尺素材から切り抜き区間を自動選定し、Gemini APIに非公開システムプロンプトを渡してフック・整文テロップ・CTA・ハッシュタグをJSON生成 | 実装済み（本リポジトリ `auto_edit_lite/edit_brain.py`）。実際のGemini APIキーでハイライト区間選定・`call_gemini()`の実呼び出し・Phase1との連結（cut→transcribe→edit_brain→trim→caption→render）までエンドツーエンドで動作確認済み（合成音声のテスト素材、本物のTikTok Shop素材1本）。モデル名は`gemini-3.8-flash`（旧`gemini-2.5-flash`は新規ユーザー向け廃止のため変更済み） |
| Phase3 | Google Drive監視フォルダ + Google Apps Script（定期トリガー） + Cloud Run（ffmpeg+faster-whisper+Gemini APIをコンテナ化）で完全自動化。素材投入→自動編集→同フォルダに書き戻し | 未着手。GCPアカウント・課金設定も未作成 |

Phase1→2→3の順に積み上げる。各フェーズは独立して価値を出せる設計。

## 4. 各フェーズ詳細仕様

### Phase1 (`lite_edit.py`)

- `cut`: ffmpegの`silencedetect`で無音区間を検出し、発話区間だけをconcatで繋ぎ直す。
  無音マージン0.15秒、0.3秒未満の隙間は結合して刻みすぎを防止。
- `trim`: Phase2が選んだハイライト区間（`highlight.json`の`start`/`end`）で
  `cut.mp4`を切り出す。長尺の元素材から切り抜き区間だけを抜き出す用途。
- `transcribe`: faster-whisper（"small"モデル、CPU/int8、`language="ja"`、
  `vad_filter=True`）で日本語文字起こし。話者分けなし。
- `caption`: 単一スタイル・固定セーフゾーンのASS字幕を生成（1080x1920基準）。
  14文字を超える行は句読点/スペース付近で必要な行数分だけ折り返す。
- `render`: 縦型(1080x1920)化 + 字幕焼き込み + `loudnorm`による音量正規化。
  `--hook-freeze`でPhase2が先頭に追加したフック秒数分、`--cta-freeze`で
  末尾に追加したCTA秒数分、映像を静止・音声を無音化して延長し同期させる
  （`tpad`のstart_duration/stop_durationは1つのフィルタ呼び出しにまとめて
  指定する必要がある。別々のtpadとして連結すると末尾側の長さ計算が崩れる
  というffmpegの制約がある。検証済み）。

### Phase2 (`edit_brain.py`)

- `HIGHLIGHT_SYSTEM_PROMPT` / `call_gemini_highlight`: 長尺素材の全文字起こし
  セグメント(インデックス付き)から、TikTok Shop切り抜き用として最も訴求力の
  高い「ひと続きの区間」を1つ選ばせる(`start_index`/`end_index`、15〜30秒
  目安、セグメント境界を尊重し文の途中で切らない)。選定理由(`reason`)も
  合わせて出力させ、`highlight.json`に実時間(`start`/`end`)として保存する。
- `SYSTEM_PROMPT`: フック（未完了状態／カクテルパーティ効果、数字なし）、
  テロップ整文（フィラー除去、12〜16文字、PAS順序保持、誇張禁止）、
  CTA（黄色ボタン誘導、数字なし）、ハッシュタグ（メーカー/商品/ジャンルの3種）、
  禁止事項（薬機法・景品表示法・虚偽性能・具体価格）、文体（タメ口・標準語）を規定。
  ハイライト区間として選ばれた部分だけ（0秒基準に振り直し済み）を入力する。
- `call_gemini` / `call_gemini_highlight`共通: `google-genai` SDK、
  `gemini-3.8-flash`、`response_mime_type="application/json"`。
  APIキーは環境変数`GEMINI_API_KEY`から取得。
- `build_seg_ai`: フックセグメント(0〜2.3秒)を先頭に追加、ハイライト区間の
  セグメントを`HOOK_DURATION+0.1=2.4秒`後ろにシフト、末尾にCTAセグメントを
  追加して`seg_ai.json`を出力。これを`trim`→`caption`→
  `render --hook-freeze 2.3 --cta-freeze 2.3`に渡す。

### Phase3（未着手）

- Google Driveの指定フォルダを監視（Google Apps Script 定期トリガー、または
  Drive push notifications）。
- 新規素材が置かれたらCloud Run上のコンテナ（ffmpeg + faster-whisper + Gemini API）
  を起動し、Phase1/2のロジックを実行。
- 完成した動画を同フォルダ（または指定の出力フォルダ）に書き戻す。
- 素人ユーザーはDriveフォルダへのファイル配置のみで完結し、コード・プロンプトには
  一切触れない。

## 5. 運用フロー（Phase3完成後の想定）

1. 編集未経験スタッフが素材動画と商品情報をGoogle Driveの指定フォルダにアップロード。
2. 定期トリガーが新規ファイルを検知し、Cloud Run上の処理を起動。
3. Phase1（無音カット・文字起こし）→Phase2（Gemini APIでフック/テロップ/CTA生成）
   →Phase1（字幕焼き込み・書き出し）の順に実行。
4. 完成動画を同フォルダに書き戻す。スタッフは結果を確認するのみ。

## 8. 検証済みバグ修正の記録

- **`cut`の無音判定バグ（修正済み）**: `lite_edit.py`の`_speech_segments`は、
  素材が無音から始まる、または無音のまま終わる場合に、その無音自体を
  `SILENCE_MARGIN`(0.15秒)分だけ発話と誤認する実装になっていた。合成テスト
  素材（無音→トーン→無音→トーン→無音の構成）で`cut`を実際に実行し、
  本来2区間のはずの発話区間が4区間に誤検出されることを確認、原因を特定して
  修正した。修正後は同じ素材で正しく2区間に戻ることを確認済み。
  通常ケース（素材の先頭・末尾が無音でない場合）への影響はない。

## 9. このセッションでの検証範囲についての注記

- 本セッションのクラウド環境には`GEMINI_API_KEY`が設定されておらず、実素材
  （動画ファイル）も存在しなかった。そのためPhase2（`edit_brain.py`の
  Gemini API呼び出し）およびPhase1の実素材での検証は今回は実施していない
  （コードレビューのみ）。
- 上記「8.」のPhase1バグ修正検証は、ffmpegで自作した合成テスト素材
  （無音/サイン波トーンのみ、音声認識可能な実音声は含まない）で行った。
  `transcribe`（faster-whisper）・`render`（`--hook-freeze`/`--cta-freeze`
  込み）もこの合成素材で一連のパイプラインがエラーなく完走することを確認した
  （文字起こし結果が空になるのはトーン音声のため想定通り）。
- 「4.」に記載のPhase2の「実際のGemini APIキーで...エンドツーエンドで動作
  確認済み」「本物のTikTok Shop素材1本」という記述は、過去のセッション
  （コミット`bcdab62`/`3b88c32`）で主張されたものだが、本セッションの環境には
  そのAPIキー・素材・検証時の出力物（画像等）が一切残っておらず、再現・
  再検証はできなかった。クラウドセッションはコンテナが使い捨てのため、
  過去セッションで一時的にAPIキーや素材が利用可能だった可能性はあるが、
  その実在性を本セッションから裏付けることはできない点を記録しておく。
