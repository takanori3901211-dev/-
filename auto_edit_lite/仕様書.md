# TikTok Shop 自動編集ツール 仕様書

## 1. 目的・背景

AnyMindのTikTok Shop事業で大量の動画投稿を行うにあたり、編集未経験のスタッフでも
素材を出すだけで一定品質の編集済み動画が自動生成される仕組みを構築する。

最終形は、素材をGoogle Driveの指定フォルダに置くだけで裏側のクラウド処理が自動的に
編集・書き出しを行う完全自動化（Phase3）。素人ユーザーは一切プロンプトやコードを
見ない運用とする。

開発自体はClaude Codeで行うが、本番稼働はClaude Code無しで動作するクラウド基盤
（GCP Cloud Run想定）に乗せる。開発・保守は現状ユーザー1人。

## 2. IP非公開方針

| 項目 | 扱い |
|---|---|
| 非公開スキル `tiktok-short-edit`（字幕ピクセル配置計算式・配色コード・タイミング計算式・VOICEVOX設定・SFX/ズームバンプ演出・話者ピッチ判定） | 簡易版には**絶対にコピーしない** |
| 「なぜ伸びるか」の判断ロジック（フック文言の作り方・PAS構成・CTAの打ち方） | Phase2のAI判断層(`edit_brain.py`)には反映してよい |
| Phase2のプロンプト・ロジック自体 | 素人ユーザーには**絶対に見せない・配布しない**（構造的にDriveフォルダ操作のみで済む設計で担保） |

## 3. 全体アーキテクチャ（3フェーズ）

| フェーズ | 内容 | 状態 |
|---|---|---|
| Phase1 | ローカル試作: ffmpeg無音カット + faster-whisper文字起こし + 単一スタイル字幕焼き込み（縦型1080x1920） | 実装済み（本リポジトリ `auto_edit_lite/lite_edit.py`）。クラウド開発環境でffmpeg・faster-whisperを実際に動かし一連の動作を確認済み（合成テスト素材）。実機（自宅Mac・本物の素材）では未検証 |
| Phase2 | AI判断層: (a)長尺素材から切り抜き区間を自動選定しフック・整文テロップ・CTA・ハッシュタグを生成、(b)ナレーション無しB-roll素材向けに商品情報のみから台本を新規生成、(c)商品が混在するB-rollクリップ群をGemini Visionで分類・絞り込み、企画（訴求軸）とカット構成を提案、(d)撮影前に商品情報のみからカット割（撮影指示書）と構図の参考イメージ（Gemini画像生成）を提案。いずれもGemini APIに非公開システムプロンプトを渡してJSON/画像生成 | 実装済み（本リポジトリ `auto_edit_lite/edit_brain.py`）。(a)はハイライト区間選定・Phase1との連結（cut→transcribe→edit_brain→trim→caption→render）、(b)は台本生成・B-roll結合・caption→render、(c)はクリップ分類・企画提案・assemble→caption→render、(d)はカット割生成・参考イメージ生成・HTML出力まで、いずれも実際のGemini APIキーでエンドツーエンドで動作確認済み（合成音声のテスト素材、本物のTikTok Shop素材=大量動画素材_切り抜き用フォルダ1本、TIRTIR手元動画素材フォルダの実クリップ、TIRTIRの実商品情報）。テキストのモデル名は`gemini-3.8-flash`（旧`gemini-2.5-flash`は新規ユーザー向け廃止のため変更済み）、画像生成は`gemini-3.1-flash-image` |
| Phase3 | Google Drive監視フォルダ + Google Apps Script（定期トリガー） + Cloud Run（ffmpeg+faster-whisper+Gemini APIをコンテナ化）で完全自動化。素材投入→自動編集→同フォルダに書き戻し | 未着手。GCPアカウント・課金設定も未作成 |

Phase1→2→3の順に積み上げる。各フェーズは独立して価値を出せる設計。

## 4. 各フェーズ詳細仕様

### Phase1 (`lite_edit.py`)

- `cut`: ffmpegの`silencedetect`で無音区間を検出し、発話区間だけをconcatで繋ぎ直す。
  無音マージン0.15秒、0.3秒未満の隙間は結合して刻みすぎを防止。
- `trim`: Phase2が選んだハイライト区間（`highlight.json`の`start`/`end`）で
  `cut.mp4`を切り出す。長尺の元素材から切り抜き区間だけを抜き出す用途。
- `transcribe`: faster-whisper（"small"モデル、CPU/int8、`language="ja"`、
  `vad_filter=True`）で日本語文字起こし。話者分けなし。
- `caption`: 単一スタイル・固定セーフゾーンのASS字幕を生成（1080x1920基準）。
  14文字を超える行は句読点/スペース付近で必要な行数分だけ折り返す。
- `render`: 縦型(1080x1920)化 + 字幕焼き込み + `loudnorm`による音量正規化。
  `--hook-freeze`でPhase2が先頭に追加したフック秒数分、`--cta-freeze`で
  末尾に追加したCTA秒数分、映像を静止・音声を無音化して延長し同期させる
  （`tpad`のstart_duration/stop_durationは1つのフィルタ呼び出しにまとめて
  指定する必要がある。別々のtpadとして連結すると末尾側の長さ計算が崩れる
  というffmpegの制約がある。検証済み）。
- `broll`: ナレーション無しのB-rollクリップ群を`--target-duration`秒に
  なるよう結合する。各クリップの実尺を上限に、短いクリップで埋まらなかった
  分を他のクリップ（特に長いクリップ）へ自動で再配分する(water-filling)。
  渡すクリップが全て同一商品であることの確認は呼び出し側の責任（後述）。
- `frames`: 各クリップの15%/50%/85%地点から代表フレームを3枚ずつ抽出し、
  `edit_brain.py plan`に渡す`manifest.json`（クリップパスとフレームパスの
  対応表）を作る。
- `assemble`: `edit_brain.py plan`が出力した`plan.json`の各セグメントが
  指定する秒数ぴったりにクリップを切り出して結合する。クリップの実尺が
  指定秒数に満たない場合は、末尾を静止させて(`tpad`)音声を無音で延長
  (`apad`)してちょうどの長さにする。

### Phase2 (`edit_brain.py`)

- `HIGHLIGHT_SYSTEM_PROMPT` / `call_gemini_highlight`: 長尺素材の全文字起こし
  セグメント(インデックス付き)から、TikTok Shop切り抜き用として最も訴求力の
  高い「ひと続きの区間」を1つ選ばせる(`start_index`/`end_index`、15〜30秒
  目安、セグメント境界を尊重し文の途中で切らない)。選定理由(`reason`)も
  合わせて出力させ、`highlight.json`に実時間(`start`/`end`)として保存する。
- `SYSTEM_PROMPT`: フック（未完了状態／カクテルパーティ効果、数字なし）、
  テロップ整文（フィラー除去、12〜16文字、PAS順序保持、誇張禁止）、
  CTA（黄色ボタン誘導、数字なし）、ハッシュタグ（メーカー/商品/ジャンルの3種）、
  禁止事項（薬機法・景品表示法・虚偽性能・具体価格）、文体（タメ口・標準語）を規定。
- `SCRIPT_SYSTEM_PROMPT` / `call_gemini_script`（`edit_brain.py script`
  コマンド）: 発話の文字起こしが無い（ナレーション無しB-roll）場合に、
  商品情報のみから台本をゼロから生成する。フック→本文テロップ(2〜4個、
  魅力→裏付けとなる処方・技術→仕上がりの描写の順)→CTAの構成、各テロップに
  表示秒数(`duration`、2.0〜4.0秒)を付与。禁止事項は`SYSTEM_PROMPT`に加えて
  「価格の安さを訴求しない」「ブランド名・商品名は入力の表記を一字一句正確に
  使う」「競合への言及・比較をしない」を追加（TIRTIRのオリエンシートのNG事項
  を踏まえた汎用的なルールとして追加）。
  ハイライト区間として選ばれた部分だけ（0秒基準に振り直し済み）を入力する。
- `CLASSIFY_SYSTEM_PROMPT` / `call_gemini_classify`（`edit_brain.py plan`
  コマンドの一部）: Gemini Vision（マルチモーダル入力）を使い、各B-rollクリップ
  の代表フレーム（複数枚、`=== clip_N ===`というテキストマーカーでクリップ
  ごとに区切って1回のAPI呼び出しにまとめて渡す）から、商品情報に記載された
  どの商品が写っているか、カットの見せ方(shot_type)は何かを分類する。
  一致する商品が無い・判別できない場合は`"unknown"`として安全側に倒す。
- `PLAN_SYSTEM_PROMPT` / `call_gemini_plan`（同コマンド）: 分類結果のうち
  商品情報に一致するクリップのみを対象に、訴求軸（企画、`concept`）と、
  各テロップの文面・対応するクリップID・表示秒数を一括で提案させる。
  テロップはペアになるクリップのshot_type/descriptionと矛盾しないように
  指示している（例: テクスチャを見せるカットには使用感、パッケージの
  カットには特長の話、など）。
- `main_plan`: 上記2つを順に呼び出し、`manifest.json`（`lite_edit.py frames`
  が出力するクリップ⇄フレーム対応表）と商品情報から`plan.json`
  （`{"concept", "segments":[{"start","end","text","clip"}], "hashtags"}`、
  `caption`コマンドがそのまま読める形式）を生成する。
- `SHOTLIST_SYSTEM_PROMPT` / `call_gemini_shotlist`（`edit_brain.py shotlist`
  コマンド）: 素材がまだ無い段階（撮影前）で、商品情報のみから「カット割
  （撮影指示書）」を生成する。各カットに、テロップ文言（`SYSTEM_PROMPT`系と
  同じ禁止事項）、表示秒数、日本語の撮影指示文(`shot_description`)、
  画像生成用の英語プロンプト(`composition_prompt`、実在のブランド名・ロゴ・
  パッケージ形状は書かせない)を持たせる。
- `call_gemini_image`（同コマンド）: `gemini-3.1-flash-image`で
  `composition_prompt`から構図・アングルの参考イメージを生成する
  （1カットにつき`IMAGES_PER_SHOT`=2枚）。実商品の外観を再現するものでは
  なく、あくまでアングル・構図・ライティングの例として使う。
- `main_shotlist`: 上記を呼び出し、`shotlist.json`（機械可読）と
  `撮影指示書.html`（画像をbase64で埋め込んだ単一HTMLファイル。ブラウザで
  開くだけで見られ、素人スタッフにそのまま送付できる）を出力する。
- `call_gemini` / `call_gemini_highlight`共通: `google-genai` SDK、
  `gemini-3.8-flash`、`response_mime_type="application/json"`。
  APIキーは環境変数`GEMINI_API_KEY`から取得。
- `build_seg_ai`: フックセグメント(0〜2.3秒)を先頭に追加、ハイライト区間の
  セグメントを`HOOK_DURATION+0.1=2.4秒`後ろにシフト、末尾にCTAセグメントを
  追加して`seg_ai.json`を出力。これを`trim`→`caption`→
  `render --hook-freeze 2.3 --cta-freeze 2.3`に渡す。

### Phase3（未着手）

- Google Driveの指定フォルダを監視（Google Apps Script 定期トリガー、または
  Drive push notifications）。
- 新規素材が置かれたらCloud Run上のコンテナ（ffmpeg + faster-whisper + Gemini API）
  を起動し、Phase1/2のロジックを実行。
- 完成した動画を同フォルダ（または指定の出力フォルダ）に書き戻す。
- 素人ユーザーはDriveフォルダへのファイル配置のみで完結し、コード・プロンプトには
  一切触れない。

## 5. 運用フロー（Phase3完成後の想定）

1. 編集未経験スタッフが素材動画と商品情報をGoogle Driveの指定フォルダにアップロード。
2. 定期トリガーが新規ファイルを検知し、Cloud Run上の処理を起動。
3. Phase1（無音カット・文字起こし）→Phase2（Gemini APIでフック/テロップ/CTA生成）
   →Phase1（字幕焼き込み・書き出し）の順に実行。
4. 完成動画を同フォルダに書き戻す。スタッフは結果を確認するのみ。

## 7. 未決定事項

- 月間想定投稿本数の確定（Phase3のコスト精度を上げるために必要）。
- メロジョイ/ビタビタ（感触・音の演出）をPhase1/2の簡易版にどこまで反映するか
  （非公開スキルの領域と重複するため要判断。現状は将来フェーズで検討扱い）。
- GCPアカウント・課金設定の作成タイミング。
- 「大量動画素材_切り抜き用」フォルダの素材は、確認した1本が既に字幕・商品名
  オーバーレイの焼き込み済み動画だった。切り抜き元として投入する素材が
  無編集のraw footageなのか、既存の編集済み動画（この場合は旧字幕の検出・
  除去や、新規テロップを追加しない運用などの対応が必要）なのか、本番素材の
  性質を確認する必要がある。
- ブランド名・商品名など固有名詞のfaster-whisper誤認識対策（`initial_prompt`
  や`hotwords`パラメータでの固有名詞リスト指定など）は未実装。
- 【実際に発生した問題・対応済み】ナレーション無しB-roll素材のフォルダ
  （例: TIRTIR手元動画素材、35クリップ）は**複数商品の映像が同一フォルダに
  混在**していることがあり、商品を確認せずにクリップを選ぶとテロップで
  紹介する商品と映像に映っている商品が一致しない動画が生成されてしまう
  問題が実際にTIRTIRの検証で発生した。`edit_brain.py plan`
  （Gemini Visionによるクリップの商品分類・絞り込み）を追加して対応したが、
  以下の限界が残っている（要改善）:
  - ブランド名・商品名が写っていない角度のフレームだと分類が「不一致／不明」
    側に倒れ、その商品の有効なクリップでも除外されてしまうことがある
    （誤って別商品を混ぜるよりは安全だが、使えるクリップが減り動画が
    単調になりやすい）。`lite_edit.py frames`は1クリップにつき3枚の
    フレームを抽出して精度を上げる対応をしたが、ブランド名が写る瞬間が
    さらに限定的な場合は不十分な可能性がある。
  - 根本的な解決策としては、Phase3運用時に「アップロード時点で商品ごとに
    フォルダを分けて管理する」運用ルールにする方が、事後のAI分類より
    確実性が高い。現状はどちらの運用にするか未決定。
- `edit_brain.py shotlist`（撮影前のカット割・参考イメージ提案）と
  `edit_brain.py plan`（撮影後のAI検証）は、現状はそれぞれ独立したコマンドで
  連携する仕組みが無い。スタッフが`shotlist.json`のカット順どおりに
  ファイルをアップロードした場合に、それを`plan.json`相当（`segments`に
  `clip`を対応させた形式）へ変換する処理は未実装（手動、または簡単な
  変換スクリプトが必要）。また、ファイル名とカットの対応付けルール
  （例: `shot1.mp4`、`shot2.mp4`...）も未確定。
- 参考イメージは実在の商品パッケージを再現しない方針でGemini画像生成を
  使っているが、ユーザーからは「TikTok Shopの実際の動画を参考に持ってくる」
  案も提示されていた。実装していない理由は、TikTok動画のダウンロード/
  フレーム抽出がTikTokの利用規約・スクレイピングの観点で複雑なため。
  オリエンシートの投稿URL一覧（例: TIRTIR_9月大量動画施策スプレッドシート）
  を使って合法的に参考動画を収集・引用する方法があれば、画像生成の代わり
  または併用として検討の余地がある。
